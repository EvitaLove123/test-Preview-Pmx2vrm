3. Humanoid mapping

Map the PMX skeleton to standard VRM Humanoid roles. Original PMX bone names remain unchanged. Finger matching supports Japanese full-width numbering and common L/R prefix/suffix conventions. Ambiguous generic Finger01 names are left unmapped rather than guessed.

6. Conversion pipeline

  • PMX parser integration — experimental browser prototype
  • ZIP package import — first prototype
  • Interactive 3D preview — first browser prototype
  • Humanoid mapping editor — first prototype
  • Automatic and manual mapping for core body and finger humanoid bones — improved side-aware aliases
  • Browser-native VRM 0.x and VRM 1.0 export buttons — connected to separate Three.js serializers; test on real PMX models
  • VRM 0.x metadata, humanoid mapping, first-person, BlendShape and optional thumbnail — implementation scaffold; validator testing pending
  • VRM 1.0 metadata and humanoid core — implementation scaffold; validator testing pending
  • Safe A-pose to T-pose adjustment — planned
  • Expressions, material conversion, SpringBone and colliders — further conversion/validation work required

This is an early PMX inspection prototype, not a PMX-to-VRM converter. Parsing and preview must still be tested with representative PMX models on Android Chrome.

7. Known limitations

  • ZIP import extracts one PMX plus common texture assets, but texture path matching and legacy formats still need model-by-model validation.
  • PMX physics, IK animation playback, toon rendering, and every MMD-specific material feature are not guaranteed in this preview.
  • Humanoid mapping includes core body and finger roles. Browser-native VRM export is now wired for testing, but both formats still need independent schema-validator and target-app checks. Expressions, MMD physics conversion, SpringBone authoring, and complete VRM validation remain unfinished.
